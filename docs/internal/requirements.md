# Simple Voice — Requirements

This document records every requirement the owner has stated for Simple Voice. It is the
source of truth for scope: a feature is done only when it satisfies the matching entry here.

## 1. Product

| ID  | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P-1 | The app is called **Simple Voice**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| P-2 | It is a Tauri 2 desktop app living in this repository (`yuyudhan/simple-voice`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| P-3 | It is built for other people to use, not only the owner: no hard-coded personal paths, keys, or vocabulary.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| P-4 | macOS first and only for now (Apple Silicon, macOS 14+; Apple Speech requires macOS 26+).                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| P-5 | Installation and updates happen only through the install script `scripts/install.sh`, published with every GitHub release at `releases/latest/download/install.sh`, which installs from the GitHub release with checksum and code signature verified, into `~/Applications` so that no administrator password is ever needed. The repo carries the script and the release automation that publishes it.                                                                                                                                                    |
| P-6 | The UI must be elegant, simple and functional, in the product's own design language, Signal (`docs/internal/design.md`); it must not imitate another product's visual identity.                                                                                                                                                                                                                                                                                                                                                                            |
| P-7 | Everything the owner's Hammerspoon dictation module does today must be done by this app instead (see § 3).                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| P-8 | Users learn about and install new releases without leaving the app: it checks for a newer release on launch and once a day (automatic checks can be turned off; "Check now" is always available), then shows a banner that can be dismissed for that version, an "Update Available" item in the menu bar and app menu, and an Install update button that runs the published install script (P-5) in the background; the script installs from the GitHub release, quits, replaces and reopens the app, and a failure is shown in the app with the log path. One click is all an update takes, with no Terminal: when a newer version is already on disk under the running app (an older script replaced it without restarting), the script restarts the app, and the app itself shows "Restart now" in the banner and Settings → App. The first launch after an update shows a dismissible banner saying it is updated and that history, dictionary and settings are unchanged. The "could not start" screen (for example a database refused under S-7) also offers "Update Simple Voice", which checks and installs the latest release (or restarts onto an installed one), or says why it cannot. |
| P-9 | The install script also uninstalls: `--uninstall` quits the app, deletes it (and a copy an older script left in `/Applications` when the user may delete it) with what macOS keeps for it under `~/Library`, and resets its permissions, keeping the data in `~/.simplevoice` for a later reinstall; `--uninstall --purge` also deletes `~/.simplevoice` and the database files in a folder the database was moved to, never that folder or anything else in it. Development builds (`.dev` identifiers) are left alone. |

## 2. Storage

| ID  | Requirement                                                                                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S-1 | A local SQLite database stores all user configuration, the dictation history, the personal dictionary, snippets (SN-1) and meetings (MT-1: transcripts, speakers, summaries, chat, translations). Meeting audio is kept beside it in `~/.simplevoice/meetings/`, one owner-only folder per meeting. |
| S-2 | Default location: `~/.simplevoice/` (database file `~/.simplevoice/simple-voice.db`).                                                                                               |
| S-3 | The database location can be changed in Settings. Changing it moves the database; the app remembers the location across restarts.                                                   |
| S-4 | On first launch the app creates the directory and the database and applies the schema without any manual step.                                                                      |
| S-5 | New app versions upgrade an existing database in place through versioned, forward-only migrations, taking a backup before migrating. Old data is never lost on upgrade.             |
| S-6 | Every SQL statement is checked at compile time (sqlx query macros with a committed offline cache).                                                                                  |
| S-7 | Opening a database written by a newer app version (a downgrade) is refused with a clear message rather than risking the data.                                                       |
| S-8 | No credentials are stored: there are no accounts and no API keys. Migration 0010 deletes the Groq and custom-endpoint keys and endpoint settings that earlier versions saved (LO-5), and `GROQ_API_KEY` in the environment is no longer read. |
| S-9 | Development builds (`just dev`) keep all their data in `~/.simplevoice-dev/`, so their migrations never change the installed release's database.                                     |

## 3. Dictation (parity with the Hammerspoon module)

| ID   | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-1  | System-wide dictation: record from the microphone, transcribe, paste into the focused input of any app.                                                                                                                                                                                                                                                                                                                                                       |
| D-2  | Two global shortcuts, both configurable in Settings: **hold to speak** (recording stops on release; default the Fn key alone) and **toggle to speak** (press to start, press again to stop; default `Ctrl+/`). Fn used as a modifier (Fn+Arrow, Fn+Delete) never starts or toggles a dictation. While Fn is a shortcut and Accessibility access is missing, the X-3 warning also appears next to the shortcut settings and names the Fn shortcuts it affects. |
| D-3  | When enabled in Settings (off by default), Esc cancels a recording in progress without transcribing. When disabled, Esc is never registered and reaches the focused app.                                                                                                                                                                                                                                                                                       |
| D-4  | Prefer the built-in microphone by default (Bluetooth headsets switch to low-quality HFP); the microphone is selectable in Settings.                                                                                                                                                                                                                                                                                                                           |
| D-5  | Languages: English, Hindi and Hinglish by default, each its own choice in the language picker. Languages are BCP 47 tags from one registry in the app (`sv_domain::languages`): a language is its base language plus the script the app writes it in, so a romanised variant is its own entry (Hinglish is stored as `hi-Latn`: Hindi in Roman script) while pure Hindi (`hi`) comes out in Devanagari. Adding a language or a romanised variant is one registry entry. Local Whisper models pick the most likely allowed language directly; the other models take the language from the model itself (Apple Speech: the first selected language's locale). The fallback language (any selected language that is not a romanised variant) is still chosen and validated in Settings, but no on-device model re-runs a dictation in it: that re-run belonged to the removed Groq transcription. Allowed languages are configurable. |
| D-6  | Personal dictionary words bias recognition (Whisper `prompt`) and are passed to the formatter as preferred spellings. The prompt is the lead of each selected language, then "Simple Voice" and "SimpleVoice", then the personal dictionary in its order, then built-in pack words (D-17), joined by `, `, capped at 850 characters and at 200 estimated Whisper tokens (Whisper keeps only the last 223 prompt tokens, so an overlong prompt would lose its lead and the user's first words); the estimate is calibrated against Whisper's multilingual tokenizer to run high over a whole prompt. Once a dictionary word does not fit, every later one is left out, keeping the dictionary's order. |
| D-7  | Replacement rules (`heard -> written`) are applied deterministically, longest phrase first, whole words, case-insensitive.                                                                                                                                                                                                                                                                                                                                    |
| D-8  | Deterministic formatting runs first: hesitation sounds removed in any elongation (`um`, `ummmm`, `uhh`, `ah`, `ahum`, `erm`, `hmm`, `e-au`) while words of the same shape stay (`err`, `hum`, `mm`, `uh-huh`), rules, internal-caps brand casing (`argocd` → `ArgoCD`), no space before punctuation, sentence capitalisation, standalone `i` → `I`. A recording of only hesitations counts as no speech. |
| D-9  | An on-device LLM formatting pass (the post-processing provider of M-6: Apple Intelligence or the local Qwen3 4B Instruct, temperature 0) then rewrites the text: drops fillers and self-corrections, keeps Hinglish word for word, writes shortcuts as `Ctrl+Shift+M`, uses conventional tech spellings, and decides the layout itself (prose, `- ` bullets, `1. ` steps). Dictated instructions or questions are formatted, never answered. |
| D-10 | The formatting pass must stay fast (~0.25 s). If it fails, times out (2.5 s + 5 ms/word), is truncated, is empty, or grows beyond 1.5× the input + 10 words, the deterministic text is pasted and marked "unformatted". Transcripts under 3 words skip it. It can be turned off.                                                                                                                                                                              |
| D-11 | Overlapping dictations never paste out of order and never share an audio file: each recording has an id and its own file; an older result arriving after a newer paste is dropped (kept in history).                                                                                                                                                                                                                                                          |
| D-12 | Audio cues on start and stop.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D-13 | A watchdog stops and transcribes after a maximum recording length (default 5 minutes).                                                                                                                                                                                                                                                                                                                                                                        |
| D-14 | A failed dictation keeps its audio so it can be retried from history; a dictation is never silently lost.                                                                                                                                                                                                                                                                                                                                                     |
| D-15 | The dictated text is placed on the clipboard and stays there by default, so it is never lost when pasting fails; a setting restores the previous clipboard after a successful paste instead. A dictation that could not be pasted is stored in history as "not pasted" with the reason, never as pasted.                                                                                                                                                      |
| D-16 | Pasted text ends in whitespace so back-to-back dictations never run together: a space is appended unless the text already ends in whitespace (for example a trailing newline). History and the clipboard copy of a retry keep the text without it.                                                                                                                                                                                                            |
| D-17 | **Built-in vocabulary** sits behind the personal dictionary. The product's name is always on: "Simple Voice" and "SimpleVoice" lead the prompt and `simplevoice` is cased `SimpleVoice` ("simple voice" is left alone, being an ordinary phrase). Ten curated packs serve the people who dictate: Everyday tech and Programming (on by default, also for existing installs), Web & JavaScript, Backend & databases, Mobile apps, Cloud & DevOps, Data & AI, Sales, Marketing, Business & finance; the user switches them in the Dictionary page's Built-in dialog, which lists each pack's terms. Every word of an enabled pack that is one letter-led word with a later capital (`GitHub`, `SaaS`, `EC2`) is a casing rule, and each pack's `heard -> written` rules (`node js` → `Node.js`, `kube ctl` → `kubectl`) apply too, however little of the pack reaches the prompt; no casing word may be an ordinary English or romanised Hindi word. Pack words enter the prompt in turns across the enabled packs, after the personal dictionary, within at most 80 estimated tokens. A phrase in the personal dictionary, as a word or as a rule's heard side, gets no built-in rule or prompt word, so the user's spelling always wins. |

## 4. Transcription engines and models

| ID  | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| M-1 | No cloud transcription (owner decision: no cloud at all). Groq Whisper was removed with every other remote provider; a saved Groq Whisper choice became Smart Select (LO-5), and history rows it produced still name it "Groq Whisper (removed)". |
| M-2 | **Parakeet** local models, as in FluidVoice: Parakeet TDT v3 (multilingual), Parakeet TDT v2 (English only), Parakeet Flash (beta, streaming English).                                                                                                                                                                                                                                                                                                                                                                                                             |
| M-3 | **Apple Speech** (on-device, macOS 26+).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| M-4 | Each model shows its speed and accuracy, its languages, whether it is ready, downloading, needs downloading (with its one-time download size) or unsupported on this Mac (with the reason), and where its files come from with their license ("Built into macOS · no download" for Apple's models). |
| M-5 | Local models are downloaded on demand from within the app, only when the user asks, with progress, and can be deleted. Besides the voice models this covers the local language model (Qwen3 4B Instruct, 2.5 GB, Apache-2.0) and the speaker diarization model (22 MB, CC-BY-4.0). |
| M-6 | Post-processing (the LLM formatting pass) runs only on this Mac, with three choices: **Apple Intelligence** (default; macOS 26+ with Apple Intelligence on), the **local model** Qwen3 4B Instruct (llama.cpp on Metal, any Apple Silicon Mac, after its download), or **Off**. Any transcription model combines with any choice, so every setup is fully offline. Apple Intelligence rejects any request containing Hindi, so it gets only the English few-shot examples and Hindi or Hinglish dictation through it falls back to the deterministic text with a reason; the local model also gets the Hinglish examples. A choice that is not ready (not downloaded, unsupported) pastes the deterministic text marked "unformatted" with the reason. |
| M-7 | Nothing needs an API key or an account: transcription, formatting, edit mode, learning and meetings all run on models on this Mac. The Groq API key fields were removed with the cloud providers. |
| M-8 | Inspired by Wispr Flow and FluidVoice, but simpler: few choices, sensible defaults, great user experience.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| M-9 | **Smart Select** (Beta) is an opt-in voice model choice next to Choose model, which stays the default (M-12): the app picks the model for each dictation from the dictation languages and what is downloaded. It only uses models on this Mac; audio never leaves it. The user only chooses languages; the models are ranked by how many selected languages each writes as chosen (script included), ties going to the more accurate and then the smaller model, and Smart Select recommends the top one for download. English only → Parakeet TDT v2; Parakeet TDT v3 languages → Parakeet TDT v3; English with Hinglish → Hinglish Whisper; other languages, pure Hindi included → Whisper Turbo. The best downloaded model in that ranking runs. When the recommended model can't write a selected language as chosen, Smart Select says so (U-7). |
| M-10 | **Local romanised dictation**: a romanised variant works fully offline when a model on this Mac writes it (Hinglish through Hinglish Whisper, Oriserve Hindi2Hinglish Prime); every language in its own script works offline through Whisper Turbo (Whisper large-v3 turbo, 99 languages). The local model chooses among the dictation languages from its own language detection and receives the dictionary prompt (D-6). |
| M-11 | Smart Select retries a dictation at most once, never in parallel, on the next downloaded model in its ranking that writes every selected language the first model writes (a retry never writes a chosen language worse; without such a model there is no retry): when the first model fails, or when "Double-check unclear dictations" is on (default) and a result of 3 or more words falls below the confidence floor (Whisper: average log-probability below -1.0 or compression ratio above 2.4; silence exempt) or, with a romanised variant among the languages, mixes that language's own script with its romanised script (e.g. Hinglish written half in Devanagari, D-5). A retry that returns text replaces the first result. Under Choose model there is no retry. Floors come from the transcription eval (`scripts/eval/transcription-eval.sh`). |
| M-12 | A new install defaults to **Parakeet TDT v3** under Choose model, so dictation needs no account and audio never leaves the Mac. Onboarding's voice model step leads with the chosen local model's card: what it offers (on-device, offline, its languages), a one-click download with its size, live progress, a retry on failure, and a ready confirmation; the full model list opens from "Choose a different model". Installs that kept the old Groq Whisper default (migration 0009) were moved to Smart Select by migration 0010. |

## 7. Engineering quality

| ID  | Requirement                                                                                                                                                                                                             |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q-1 | `.editorconfig` with 4-space indentation everywhere.                                                                                                                                                                    |
| Q-2 | Quality gates like the `moneytrace` and `kalki` repositories: git hooks (pre-commit, commit-msg, pre-push), guard scripts, `just` recipes, CI.                                                                          |
| Q-3 | Rust: `unsafe` code is forbidden in every crate; strict clippy (no `unwrap`/`expect`/`panic`, no lint suppressions, no `todo!`).                                                                                        |
| Q-4 | Compile-time checked SQL via sqlx; runtime SQL strings are banned by a guard.                                                                                                                                           |
| Q-5 | Code is organized as a Cargo workspace split into crates by responsibility (`sv-domain`, `sv-storage`, `sv-text`, `sv-audio`, `sv-engine`, app) and, inside each crate and the UI, vertically by feature. There is no cloud crate. |
| Q-6 | Rust code that needs `unsafe` (Objective-C / C APIs) lives in the Swift engine helper instead, so every Rust crate forbids `unsafe`.                                                                                    |
| Q-7 | This requirements document is kept up to date as requirements are added or changed.                                                                                                                                     |
| Q-8 | `just build` produces a sealed, ad-hoc signed bundle (entitlements and hardened runtime applied) when no Developer ID is configured, so microphone access works in local builds; `APPLE_SIGNING_IDENTITY` overrides it. |
| Q-9 | `just dev` checks query macros against a freshly migrated development database, so editing a query never breaks the dev loop before the offline cache is regenerated.                                                   |

## 8. Edit mode

| ID | Requirement |
| ---- | ----------- |
| ED-1 | Edit mode rewrites the text selected in any app's input (a Gmail compose box or a browser search field included) by a spoken instruction: select the text, press the edit shortcut, say how to change it ("make this more formal", "turn this into bullets"), press it again. The edited text replaces the selection in place; Cmd+Z in that app undoes it. No command mode: edit mode never runs commands or controls the Mac. |
| ED-2 | The edit shortcut is its own toggle key combination ("Toggle to edit"), configurable in Settings → Dictation (default `Alt+Slash`, ⌥/) and can be turned off; while on, the sidebar status shows it beside the dictation shortcuts. Pressing it during any recording stops that recording. It can be neither Fn nor either dictation shortcut; a stored default that collides with a dictation shortcut starts off, and when only the edit shortcut cannot be registered at launch the dictation shortcuts still are. |
| ED-3 | The selection is read when the shortcut goes down: through Accessibility where the app exposes it, otherwise by a synthetic Cmd+C after which the user's clipboard is restored. Nothing selected, a selection over 4,000 characters, or missing Accessibility access ends the edit with a message saying so, and nothing is pasted. |
| ED-4 | The instruction is transcribed with the configured voice model and applied by the configured on-device post-processing provider (Apple Intelligence or the local model, M-6), with the selection treated as data and never as instructions. With post-processing off, edit mode says it needs a provider. |
| ED-5 | A failed, empty, truncated or timed-out edit (6 s + 20 ms per selected word, at most 30 s) leaves the selection untouched and says why. The selection's leading and trailing whitespace is kept. |
| ED-6 | The edited text is pasted only into the app the edit started in; when another app is frontmost by then, it is copied to the clipboard and the edit is recorded as not pasted. Delivery otherwise follows D-11 and D-15. |
| ED-7 | The overlay pill marks an edit with a pen from recording to result and reads "Editing" and "Edited". History keeps each edit (the instruction, the replaced selection, the result, status and models) with an Edit badge; it is searchable by the replaced text, counts the spoken instruction's words in Insights, and is excluded from formatting-pass timings. Edits keep no audio and cannot be retried. |

## 9. Learning from corrections

| ID | Requirement |
| ---- | ----------- |
| LC-1 | "Learn from your corrections" is a setting in Settings → Formatting, next to the post-processing provider it needs, off by default. Its description says that the field a dictation was pasted into is read for up to a minute and that only the changed words go to the on-device post-processing model. It needs a post-processing provider: with post-processing off the toggle is disabled and says so, and nothing is watched. No permission beyond Accessibility (X-1) is needed. |
| LC-2 | After a dictation is pasted (never an edit-mode result), the engine helper finds the pasted text in the focused field and follows it while the user edits for up to 60 s. The watch ends when focus leaves the field, when the next recording starts, or when the field is cleared (a message sent with Enter), keeping the text as it read just before the clear. Secure (password) fields are never read. |
| LC-3 | It works where the field's text is exposed to Accessibility: native (Cocoa and WebKit) apps, Electron apps (the helper sets `AXManualAccessibility`), and Chromium browsers (the helper sets `AXEnhancedUserInterface`, only for apps with a Chromium renderer). Terminals and canvas editors are skipped silently. A corrected dictation keeps the corrected text in history. |
| LC-4 | Only word substitutions of at most three words per side are candidates; punctuation-only changes, pure insertions or deletions, and rewrites (more than half the words changed) are ignored. The candidates, each with a few words of context, and nothing else of the field, are given to the configured on-device post-processing model, which answers with the numbers of those worth learning (names, brands, technical terms, unusual spellings or capitalisation; never synonyms, grammar fixes, ordinary words, numbers or romanisation variants). Answers outside the offered numbers are ignored. |
| LC-5 | Chosen corrections are added to the dictionary as plain words (D-6) marked learned; never as replacement rules. A word already in the dictionary is not added again. |
| LC-6 | Deleting a learned word records it as rejected, and it is never learned again; adding it by hand (or importing it) lifts the rejection. Editing a learned word makes it the user's own entry. |

## 10. Local only and privacy

| ID | Requirement |
| ---- | ----------- |
| LO-1 | Every model runs on this Mac (owner decision: no cloud at all): transcription, live transcript, formatting, edit mode, learning, and every meeting step (transcription, speaker diarization, summary, answers, translation). No dictated or meeting audio, transcript, field context or other user content is ever sent off the Mac. |
| LO-2 | The only network requests are the model downloads the user starts (Hugging Face; new models at a pinned revision), the update check against GitHub's latest release (daily, can be turned off; P-8) and the update install the user starts (P-5). None of them carries user content. |
| LO-3 | Apple Speech uses only on-device recognition (`SpeechTranscriber`, which has no server path), and Apple Intelligence only the on-device Foundation Models. |
| LO-4 | There are no accounts, API keys or telemetry. Logs never carry transcripts, field text or meeting text. |
| LO-5 | Upgrading to the local-only version (migration 0010) keeps history, the dictionary and every other setting: a saved Groq Whisper voice model becomes Smart Select (the best downloaded local model for the languages), a saved Groq or custom-endpoint formatting provider becomes Apple Intelligence, and the stored Groq and custom API keys, formatting model, base URL and model are deleted. History rows recorded by the removed providers keep their model ids and show them as removed ("Groq Whisper (removed)"). |
| LO-6 | Personal use only (owner decision): one user on one Mac, with no team, sharing or sync features. |

## 11. Snippets

| ID | Requirement |
| ---- | ----------- |
| SN-1 | Personal snippets live on a Snippets page: each has a spoken trigger (1–6 words, at most 60 characters, unique ignoring case) and a text (at most 4,000 characters, kept exactly as saved, newlines included); the list is sorted by trigger and can be added to, edited and deleted. Changes reach every open window at once. |
| SN-2 | Saying a trigger in a dictation (and in its retry from history; not in edit mode) pastes the snippet's text in its place: whole words, ignoring case, longest trigger first, in a single pass, so an expansion is never expanded again. Punctuation and spacing around the trigger stay. |
| SN-3 | The AI formatting pass never rewrites a snippet: each expansion reaches the model as a marker it must copy, and the text is put back afterwards. A reply that loses, duplicates or alters a marker is rejected and the deterministic text with the snippets expanded is pasted, marked "unformatted". With formatting off or skipped, snippets are still expanded. |
| SN-4 | Snippets are stored only in the local database (S-1). |

## 12. Context

| ID | Requirement |
| ---- | ----------- |
| CX-1 | "Use text around the cursor" (Settings → Dictation → Context, off by default): when a dictation starts, the helper reads at most 2,000 UTF-16 units of the focused field around the caret through Accessibility. Names, acronyms and mixed-case words from it, nearest the caret first (at most 24 terms, 400 characters together, 40 per term; number-, id- and key-like tokens dropped), prime the Whisper prompt and the formatter's preferred spellings for that dictation only, after the dictionary and pack words. |
| CX-2 | "Use names from your code editor" (off by default, only for apps in the Code category): the file names in the editor's window title and text, and the camelCase, PascalCase, snake_case or SCREAMING_CASE identifiers visible in the focused editor text, are added the same way. Nothing is run and no project folder is opened. |
| CX-3 | Apps on the exclusion list (by default 1Password 7 and 8, Bitwarden, Keychain Access and Passwords; the user can add any app from the known apps or by bundle id, and remove entries) are never read, and secure (password) fields never give text or a title. The field text is used once on this Mac and never stored, logged or sent anywhere; only the app's bundle id and why nothing was read are logged. |
| CX-4 | Context never delays dictation: the read runs beside the recording start (600 ms limit) and the pipeline waits at most 800 ms for it at stop. A read that fails, reports a reason, or lands in another app than the one the recording started in gives no hints. |

## 13. Live transcript

| ID | Requirement |
| ---- | ----------- |
| LT-1 | "Live transcript" (Settings → Transcription, on by default) shows the words while the user speaks, in the main window and in the floating pill, when the voice model streams: Parakeet TDT v3 and v2, Parakeet Flash and Apple Speech do; Whisper Turbo and Hinglish Whisper do not, and the toggle says so. Under Smart Select the top-ranked model decides. |
| LT-2 | The live text separates the words the model has committed from its current guess, which may still change, and updates at most about 8 times per second. |
| LT-3 | It is display only: when the recording stops or is cancelled the stream is cancelled, and the pasted text always comes from the normal transcription of the whole recording, as without the live transcript, so it never repeats or loses a segment. |
| LT-4 | A stream that cannot start within 10 s, fails, falls behind (8 s of audio queued in the app, or 30 s in the helper) or loses the helper only ends the live display; the dictation itself goes on. |

## 14. Meetings

| ID | Requirement |
| ---- | ----------- |
| MT-1 | Meetings are recorded only when the user starts one on the Meetings page and end only when the user stops or discards it; nothing records automatically and one meeting records at a time. Each has a title (default "Meeting" with the date and time), and is kept with its audio until the user deletes it (S-1). |
| MT-2 | The microphone is always recorded, straight to a file, so a long meeting never accumulates in memory; the elapsed time shows while it records. Stop ends the recording and starts processing; Discard removes the recording and its audio. |
| MT-3 | System audio (what the Mac plays: the other side of a call) is recorded only when the user opts in for that meeting: the start dialog asks every time, preselected with the last choice. It needs the Screen & System Audio Recording permission; without it the start is refused with how to grant it, or the user records the microphone only. If system audio stops during the meeting, the microphone keeps recording and the meeting says so. |
| MT-4 | Meetings are transcribed with the dictation voice model (Smart Select's top-ranked local model when Smart Select is chosen) and need the speaker diarization model (Speaker Diarization, 22 MB, CC-BY-4.0: pyannote community-1 with WeSpeaker and BUT PLDA, Core ML by Fluid Inference). A meeting cannot start, or be processed, until both are ready; the reason names the model to download. |
| MT-5 | Processing is bounded however long the meeting: microphone and system audio are mixed on disk, transcribed in 4-minute windows that overlap by 4 s with timestamps (each stretch kept once), and diarized from disk; each transcript segment gets the speaker who talks longest during it. Progress shows while it runs. |
| MT-6 | The transcript is editable: speakers ("Speaker 1", "Speaker 2"… in order of first appearance) can be named, and a blank name restores the label; each segment's text can be corrected; the meeting can be renamed. |
| MT-7 | A summary with action items (with an owner and a time in the meeting when the model gives them) is written on request by the meeting assistant (MT-11). Long transcripts are summarized in bounded parts that are then merged; a reply that is cut off or does not follow the format fails instead of being stored. A new summary replaces the old one. |
| MT-8 | Questions about the meeting (up to 1,000 characters) are answered only from transcript excerpts retrieved for the question, with citations that point at the transcript segments and their times; questions and answers are kept with the meeting. |
| MT-9 | The transcript is translated by a dedicated on-device translation model, MADLAD-400 3B MT (`madlad400-3b-mt`, Q4_K_M GGUF, 1.86 GB, Apache-2.0, a separate user-started download), independent of the meeting assistant. Each segment is translated on its own, in bounded batches that can be cancelled. Targets are registry languages in their own script; a romanised variant (Hinglish) is refused instead of being returned as the base language, and a language the model lacks is refused with an explicit error. Each language's translation is kept and replaced when translated again, and the last language chosen is remembered. The UI marks translations as unverified machine translation and shows the source line under each one. General chat models (Qwen3 4B and 8B) were rejected for translation after they swapped weekdays and names in offline tests. |
| MT-10 | Every long job (processing, summary, answer, translation) runs one at a time per meeting and can be cancelled, which stops the on-device work. Cancelled or failed processing keeps the audio, shows the reason, and can be retried. A quit or crash during recording or processing leaves the meeting failed with its audio repaired and kept, so it can be retried. |
| MT-11 | The meeting assistant (summary and answers) is the local model (Qwen3 4B Instruct, the default) or Apple Intelligence, chosen with the meeting setup, which also shows each model's size, license and readiness. Everything stays on this Mac (LO-1). |
| MT-12 | A meeting exports to a file the user chooses as Markdown, plain text (title, time, summary with action items, transcript with times and speakers) or JSON (everything). Deleting a meeting removes its transcript, summary, answers, translations and audio. |
